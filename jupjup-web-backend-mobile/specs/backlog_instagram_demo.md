## 사용자 결정 (2026-11-02)
- T25h 사람 판단(골든 표본 24건 검수, 판정기 라벨 문장 100·핵심 사실 60)은 **사용자가 직접** 한다.
- Instagram 수집은 **로그인 없는 공개 메타태그(og: 캡션, 대표 이미지, 작성자)만** 쓴다. 인증·접근 제한 우회 금지. 막히면 실패 사유를 표시한다.

## 요구사항 요약
1. 실제 Instagram 게시물·여러 장 게시물·Reels URL 입력 → 실제 인제스트 파이프라인 실행 (예시 데이터·mock 결과 금지)
2. 수집 → 추출 → 분석(T25h 채택 로컬 분석기) → 기존 분류 체계(대표 태그, 세부 태그, save_intent 등)로 자동 분류 → 저장·검색 가능
3. 단계별 진행 상태(대기·진행·완료·실패), 단계별 처리 시간, 오류 정보. 실제 잡 상태 기반, 가짜 진행률 금지
4. 화면: URL 입력 / 진행 / 결과(미리보기, 요약, 태그, 분류, 근거) / 분석 기록
5. 기존 데모 앱(src/jupjup/demo, 루프백 바인드)과 인제스트 API·잡 구조 재사용, 기존 동작 무회귀
6. 단일 명령으로 로컬 실행, 실제 Instagram URL E2E 테스트 수행·보고
7. 최종 보고: T25h 확인, 재사용/신규, 구현 내용, 실제 게시물 결과, 분류 검증, 실행 명령·URL, 문제와 해결, 미구현·제약

## PM이 미리 확인한 제약
- 현재 fetch/extract는 일반 HTML og 메타 추출만 한다. Instagram 전용 처리 없음.
- 분석기는 텍스트 전용이다. 이미지 내용 분석(비전)과 Reels 음성 전사는 미구현 → 캡션 기반 분석이 기본이며, 이 제약을 화면과 보고서에 밝힌다.
- 원문은 기기 밖으로 나가지 않는다(로컬 모델). Instagram에서 받아오는 것만 네트워크를 쓴다.

## 추론 과정 표시 요구 (2026-11-02 사용자 명확화)
"추론 과정"은 Claude 내부 사고가 아니라 줍줍 NLP 파이프라인의 실제 처리와 결과다. 데모와 보고서에 다음을 보여준다.
1. 입력: 원본 URL, 분석 대상 콘텐츠
2. 전처리: 본문 추출, 정제, 정규화, 토큰화, 청킹
3. 모델 처리: 로컬 모델 이름·sha256·프로필, 프롬프트 버전, 단계별 입력·출력, 재요청 횟수, map-reduce 조각
4. 결과: 키워드, 요약, 태그, 분류
5. 근거: evidence 구절, 검증기 결과, 판정기 점수, 실제 제공되는 점수·중간 출력
6. 실행 로그: 잡 단계 상태, 처리 시간, 오류
없는 값은 만들지 않는다. 검색 쪽은 같은 형식으로 phase-2-demo-search-trace에서 먼저 구현한다.

# 콘텐츠 상세 및 정리 진행 QA

## 결정

- PM 작업 트리의 상세 화면, 아카이브 스타일과 브라우저 즐겨찾기 변경을 기준으로 가져왔다. PM의 다른 미커밋 파일은 수정하지 않았다.
- 작업 API의 `status`, `current_stage`, `steps`만으로 한국어 진행 경로를 표시한다. 완료는 서버가 해당 단계에 `succeeded`를 반환했을 때만 표시하며, 퍼센트나 예상 완료 시간은 만들지 않는다. 마지막 확인 시각은 서버 변경 시각이 아니라 클라이언트의 마지막 성공 조회 시각이다.
- 대기·진행·재시도·확인 대기는 2초 간격으로 조회하고, 조회 오류에도 재시도한다. 종료 상태에서는 자동 조회를 멈추며 수동 상태 확인을 제공한다. 상태 문구는 하나의 polite live region으로 알린다.
- 따뜻한 기존 화면을 유지하면서 경로, 빈 태그, 긴 텍스트 줄바꿈, 키보드 포커스, 작은 화면과 모션 감소를 보강했다. 원문 보기와 YouTube 원문 대체 입력 및 메타데이터 수집을 유지했다. 계정별 쿼리 범위와 인증은 변경하지 않았다.
- 기존 PRD는 백엔드 검색 MVP 설계로 이 화면의 시각 명세를 제공하지 않는다. 기존 제품 화면과 이번 요청을 기준으로 했다. 백엔드 변경은 필요하지 않았다.

## 검증

- `npm run typecheck`: 통과.
- `npm test`: 15개 파일, 82개 테스트 통과. 단계 렌더링 및 상태 문구, 폴링 정책을 추가 검증했고 기존 통합 테스트에서 편집, 재분석, 삭제, 원문 복구 및 메타데이터 흐름을 확인했다.
- Impeccable detector를 변경 UI 대상에 정확히 한 번 실행: `[]`.

## 남은 사항

- 실제 백엔드/인증 세션을 연결한 데스크톱·모바일 시각 검사는 수행하지 않았다. 테스트는 jsdom과 모의 API 응답 기준이다.
- 자동 확인 간격은 고정 2초이며 브라우저가 백그라운드일 때 라이브러리 기본 동작을 따른다. 서버 워커 지연의 원인이나 완료 예상 시간은 API가 제공하지 않아 표시하지 않는다.

## Loop 2 — 77점 검수 반영

- 즐겨찾기를 인증 세션의 사용자 ID와 실제 API URL 범위로 저장하고, 로그아웃·계정 전환·재로그인과 다른 탭의 저장소 변경 시 다시 읽는다. 기존 개발 사용자 키는 계정 소유자를 알 수 없어 이관하지 않는다.
- 상세, 카드 및 즐겨찾기 목록이 같은 상태를 사용한다. 즐겨찾기 목록은 서버 페이지를 순차 조회해 뒤 페이지 항목도 찾으며 기존 필터와 보기 설정을 유지한다.
- 확인 단계의 `approved`와 `rejected`를 명시하고, 실패 재시도와 관리 메뉴 재분석에 동일한 원문 가용성·스냅샷·서버 오류 조건을 적용했다.
- 검증: `npm ci` 성공, `npm run typecheck` 통과, `npm test` 16개 파일 87개 테스트 통과. 계정 전환/재로그인, 상세·목록·재방문·후속 페이지, 승인/거절 및 재시도 불가 사례를 모의 API로 검증했다.
- 실제 백엔드 및 브라우저 시각 검사는 수행하지 않았다. 즐겨찾기는 브라우저 로컬 저장이며 목록 전체 페이지 조회는 항목 수에 따라 요청이 늘어난다. 기존 백엔드 PRD와 달라진 인터페이스는 없다.

# Phase 2 T25t — 로컬 분석기 dev 튜닝과 승격 후보 평가

**최종 상태: 디스크 중단 조건 발동으로 부분 완료.**

작성: Codex-Primary. 실행일: 2026-11-03~04 (KST). 작업 트리: `phase-2-t25t-tuning`. 시작 커밋: `ba6b5216026a551a7c72a610300c8cf6a59c7e77`. 판정기는 사람 라벨 전이므로 `deterministic_only`다. 설계 기준은 `design_local_analyzer.md` 4.2·4.4·8.6절과 `prd_and_design.md` 3.5.4절이다.

## 범위와 실험 규칙

- 분석기 튜닝·품질·지연 측정은 ingest v2 **dev 48건만** 사용한다. 실제 후보 test는 열지 않는다.
- 검색 연결용 시드 200건은 최종 설정에서만 녹화한다. 연결 품질은 검색 **dev 질의만** 평가한다. PM의 자원 절약 지시에 따라 dev 상위 2개만 seeds·linkage·반복 recorded 리포트·독립 live 벤치를 실행한다. 하위 2개는 dev 비교만 수행하며 제외 사유와 이후 명령을 남긴다.
- 프롬프트 v3의 새 예시는 직접 작성한 도서관 지도 수업과 공방 유리 수업이다. 골든 항목을 예시로 복사하지 않았다.
- 기존 `local-*` 프로필과 v2/ds-1 녹화를 보존하고 `tuning-*` 프로필을 별도로 추가한다. 기본값은 `mock`이다.
- 후보당 최대 4라운드. 기준과 검증 정본은 완화하지 않는다. 모델과 원문은 로컬에서만 처리한다.
- 하드웨어: Apple M5, 24GiB 통합 메모리, Metal, `llama-cpp-python 0.3.36`, n_ctx 16384, n_threads 4, 순차 추론.
- 긴 실행은 `caffeinate -i`로 보호하고 AC 전원의 시스템 절전도 막도록 `caffeinate -ims -w <최종 큐 PID>`를 추가했다. `pmset -g assertions`에서 PreventSystemSleep=1을 확인했다. 최종 실행 도우미는 5초마다 디스크 여유를 검사하고 15GB 아래에서 중단한다.

### R1: 공통 v3 / ds-2

가설: 원문 표현을 유지하는 추출형 요약, 명확한 enum·분류 설명, 짧은 근거와 부가 태그가 문장 수·근거 오류와 긴 출력을 줄인다. 요청 시간 상한으로 긴 꼬리를 억제하되 실패율 증가 여부를 함께 측정한다.

변경:

- analyze/chunk/reduce/repair **v3**. summary는 원문 핵심 2~4문장의 표현을 유지하고 숫자·조건·제외사항을 보존한다. 새 출력 예시와 재요청 지시는 직접 작성했다.
- 디코딩 **ds-2**: evidence 최대 6→4, claim 최대 80자, topics 5→3, keywords 10→6. 검증 스키마는 그대로다. ds-1 정책과 해시는 보존한다.
- analyze/repair/chunk 타임아웃은 30/12/30초. 출력 상한 analyze 1536, chunk 768토큰. 잘림 재시도는 기존 설계대로 1회 ×2(각각 절대 최대 3072/1536)다.
- single 입력 8000→6000, chunk 목표 4000→3000, 겹침 200→150, 최대 청크 12→8. 초과분은 기존 partial/truncation 정책을 따른다.
- R1은 소형 두 후보에 적용한다. 승격 후보는 Qwen2.5-7B와 Kanana-1.5-8B를 **분석기**로 사용하며 아래 R2 절의 최종 공통 시간 제한으로 첫 평가를 시작한다.
- CLI에 `--linkage-split`을 추가해 dev 연결 질의만 평가할 수 있게 했다. 기존 기본 동작(`all`)과 검색 순위는 유지한다.

추가 발견/수정: 분석기 조립은 판정기와 달리 오류 사이드카를 연결하지 않아 타임아웃이 recorded에서 캐시 미스로 바뀌었다. `build_eval_analyzer`에 기존 오류 사이드카를 연결했다. 원문·출력은 오류 파일에 저장하지 않으며 오류 코드/재시도 가능 여부만 저장한다. 성공으로 바꾸지 않고 타임아웃 그대로 재생한다. 성공 응답 파일이 없는 오류 전용 녹화도 재생할 수 있게 했다. 이는 프롬프트/디코딩 튜닝 라운드를 추가하는 변경이 아닌 녹화 배선 수정이다.

### v3b (소형 R3 / 승격 R2)

7B에서도 핵심 사실·엔티티 재현율이 낮아 단일 도서관 예시와 2문장 중심 출력, 3~5개 태그, '일반 명사는 제외'라는 범위가 지나치게 좁을 수 있다. 시간 제한 효과를 먼저 분리 측정한 뒤 다음을 공통 조건으로 평가한다.

- 대표 태그는 정본 범위 3~7개를 쓰고, 정보가 충분하면 5~7개로 주제·대상·활동·지명을 담는다. 원문 해시태그를 활용한다.
- 기관 외 상호·시설·메뉴·제품·작품·행사도 추출하도록 엔티티 범위를 명확히 한다.
- 직접 새로 작성한 두 합성 예시(아침숲 메밀 팬케이크, 새롬기기 돌담 K8)와 청크 예시(별빛 자료관)를 사용한다. 실제 dev 항목은 복사하지 않는다.

### v3c / ds-3 (소형 R4 / 승격 R3)

v3b Kanana-2B는 40/48 성공, 첫 시도 0.5625, 최종 0.833333이었다. 태그 F1 0.339818, 엔티티 F1 0.237361, 장소 F1 0.772817, 카테고리 0.4, 저장 의도 0.55, 핵심 사실 0.272917, 비충실 0.125, 주입 저항 0.0이었다. 주입 항목은 `ANALYSIS_SCHEMA_INVALID`로 실패했다. 검증의 `injection_echo`는 관측되지 않았으므로 공격 수행으로 단정하지 않는다.

원인 집계(모든 dev 시도): evidence_ungrounded 67, summary_sentence_count 21, summary_not_korean 3. 제품 엔티티 TP/FP/FN=8/43/4, 장소 FN=25, 사람 FN=17. 성공 40건 중 태그 7개가 22건이었다. 상세 숫자·분류 혼동은 `v3b-kanana2b-diagnostics.json`에 저장하고 원문·이름은 집계 출력에 포함하지 않았다.

가설: 추상적으로 다시 쓴 근거를 재요청으로 고치기보다 생성 단계에서 현재 원문 구절을 고르게 하면 근거 오류와 지연을 줄인다. 과도한 태그·일반 명사의 product 분류는 정밀도를 해친다.

변경:

- **입력별 source_span enum**: single은 현재 원문, reduce는 실제 제공한 source_head·노트의 source_sentences·quotes만 사용한다. 문장/인접 문장 쌍과 긴 문장의 겹친 창에서 최대 64개, 각 120자 이하를 고르게 선택한다. 원문의 실제 연속 구절과 정규화 후 근거 일치를 모두 확인한다. 다른 항목·정답 라벨을 사용하지 않는다.
- **ds-3**: source_span을 claim보다 먼저 생성, evidence 최대 3개, claim 최대 60자, 대표 태그 최대 5개. detail_tags의 category·topics·keywords·locations·entities를 디코딩에서 필수로 한다. 정본 검증 스키마는 그대로다. 필수 속성 추가를 제약 강화로 인식하도록 하위 스키마 검사를 정정했고, 필수 속성 삭제는 계속 거부한다.
- 선택 규칙 버전·구절 수·창 길이·샘플링·필수 필드·정규화 옵션을 ds-3 동결 해시에 포함한다. 요청별 enum은 기존 스키마 지문을 통해 녹화 키에 들어가며 원문 후보 목록은 녹화 파일에 저장하지 않는다.
- **v3c**: 태그 3~5개, 이름 있는 인물·장소·기관·작품 우선, 구체 제품/주요 메뉴만 product. 건강·기술과 업무/학습 분류를 명확히 하고 원문이 영어여도 요약·claim은 한국어로 쓴다. 직접 작성한 영어 연구 합성 예시(Mira Cho, Night Light Survey)를 추가한다. 기존 두 합성 예시는 저장 메모가 없는 경우의 추론을 보여 준다.
- 검증을 통과한 중복 저장 의도 라벨은 ds-3에서만 순서를 보존해 중복 제거한다. 잘못된 라벨·확률을 유효하게 바꾸지 않는다. 원래 프로필과 mock 경로는 보존한다.
- 새 경로의 문자 창·원문 근거·리듀스 범위·정본 불변·요청 키·동결 해시·중복 라벨을 테스트했다. 실제 llama.cpp 문법 컴파일(3개/64개 합성 구절)도 성공했다.
